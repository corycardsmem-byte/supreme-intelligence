# Launch Plan

## Goal
Launch a public beta with a real product experience, stable onboarding flow, and trust-aware architecture.

## Phase 1 — internal validation
- auth flow works
- chat flow works
- retrieval and citations work
- truth gate runs
- scorecard output works
- logs are complete
- billing sandbox works

## Phase 2 — closed beta
- invite-only access
- usage analytics
- feedback collection
- policy and trust review
- performance and reliability testing

## Phase 3 — public beta
- landing page
- usage tiers
- user onboarding
- support flow
- issue reporting and triage

## Phase 4 — general availability
- public launch
- enterprise onboarding
- marketing and partnerships
- support automation
- roadmap and product iteration

## Release gate
Release only when authentication, billing, evidence, policy checks, performance, and observability are functioning in staging and production-like environments.
